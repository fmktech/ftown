# CI validation

The six secret-free validation jobs use the fixed entry point `scripts/ci/run-job.sh`: `e2e`, `unit`, `release-artifacts`, `gitleaks`, `bridge-version`, and `centrifugo`. Their existing workflow events, job IDs and release matrix remain in GitHub Actions. Two platform unit jobs in `.github/workflows/unit.yml` run their steps directly instead: `unit-minimal` removes `zsh`, `tmux` and `jq` on an ubuntu runner before the bridge suite, and `unit-macos` runs the bridge and ui suites on `macos-latest`. `run-job.sh` and its setup helper pin Linux x86_64, and `unit-minimal` has to control its own tool set. The minimal job is required now that the session shell resolver (P1.1) and all four Node hook ports (P1.3) have landed. All jobs run on GitHub standard hosted runners (`ubuntu-latest` except `unit-macos`) for internal PRs, fork and Dependabot PRs, pushes and dispatches alike, with no provider key and no sandbox backend. This repository is public, so standard hosted runners are free.

The runner image already provides Docker with Compose v2, passwordless sudo and Node 24 (pinned by `actions/setup-node` and verified by `scripts/ci/setup-runtime.sh`); `run-job.sh` installs Playwright's Chromium and its OS dependencies per run, and the e2e suite brings up its own Postgres, Centrifugo and HTTP shim with Docker Compose on the runner. E2E is split into three shards, each running one isolated stack; unit suites run in the `unit`, `unit-minimal` and `unit-macos` jobs. The `unit` job installs `tmux` and `zsh` before the suites so the opencode child-launch regression runs on the runner. The regression fails when `CI=true` and either tool is missing, and skips only outside CI. Observed hosted durations are recorded on PR #225 and fit comfortably inside the existing 45-minute job deadline (the full GitHub job limit is 6 hours).

E2E runs the build, isolated local database, security and full Playwright checks with recorded-PID and Docker teardown. The workflow uploads the fixed Playwright report, test-results, UI/bridge logs and failure infrastructure log for seven days even after failure. GitHub-hosted publishing, deployment and production migration remain separate and retain their existing permissions and gates.
