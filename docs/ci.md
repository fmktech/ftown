# CI validation

The five secret-free validation jobs use the fixed entry point `scripts/ci/run-job.sh`: `e2e`, `release-artifacts`, `gitleaks`, `bridge-version`, and `centrifugo`. Their existing workflow events, job IDs and release matrix remain in GitHub Actions. Every job runs directly on the GitHub standard hosted runners (`ubuntu-latest`) through `.github/actions/run-ci` — internal PRs, fork and Dependabot PRs, pushes and dispatches alike — with no provider key and no sandbox backend. This repository is public, so standard hosted runners are free.

The runner image already provides Docker with Compose v2, passwordless sudo and Node 24 (pinned by `actions/setup-node` and verified by `scripts/ci/setup-runtime.sh`); `run-job.sh` installs Playwright's Chromium and its OS dependencies per run, and the e2e suite brings up its own Postgres, Centrifugo and HTTP shim with Docker Compose on the runner. E2E is split into three shards, each running one isolated stack; the first shard also runs the unit suites. Observed hosted durations are recorded on PR #225 and fit comfortably inside the existing 45-minute job deadline (the full GitHub job limit is 6 hours).

E2E runs the existing unit, build, isolated local database, security and full Playwright checks with recorded-PID and Docker teardown. The workflow uploads the fixed Playwright report, test-results, UI/bridge logs and failure infrastructure log for seven days even after failure. GitHub-hosted publishing, deployment and production migration remain separate and retain their existing permissions and gates.
