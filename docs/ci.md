# CI validation on Boat

The five secret-free validation jobs use the fixed entry point `scripts/ci/run-job.sh`: `e2e`, `release-artifacts`, `gitleaks`, `bridge-version`, and `centrifugo`. Their existing workflow events, job IDs and release matrix remain in GitHub Actions. The GitHub-hosted controller authenticates to Boat with the repository's `BOAT_API_KEY`, a CI-scoped key that expires 2027-01-26T17:12:04Z; rotate it before expiry. No key or controller configuration is passed to the VM. Internal PRs, pushes and dispatches require Boat; a missing key or provider failure fails the check. Fork PRs and PRs authored or triggered by Dependabot use the same fixed payload locally on an ephemeral GitHub runner without the Boat key. PR workflows are a trusted repository-writer boundary; do not grant write access to untrusted principals.

Each Boat job uses a fresh sandbox with account environment and snapshots disabled. E2E uses the default size and a 2700-second TTL, other jobs use small VMs and a 1200-second TTL. The remote execution limit is at most 2100 or 900 seconds respectively; the controller reserves time for deletion within the 45- or 20-minute GitHub job deadline. The exact checkout revision is archived, and history is bundled only for Gitleaks and bridge version checks. No account environment, provider credentials, GitHub token or production data is transferred. The controller records the sandbox ID, requests deletion on success, failure or cancellation and verifies the provider's not-found result. TTL limits resource lifetime if the controller is forcibly lost; investigate an unconfirmed deletion.

E2E runs the existing unit, build, isolated local database, security and full Playwright checks with recorded-PID and Docker teardown. It retrieves only the fixed Playwright report, test-results, UI/bridge logs and failure infrastructure log into isolated staging; symlink or special-file artifacts are rejected. The workflow uploads them for seven days even after failure. A failed artifact transfer fails an otherwise successful job, and cannot hide a test failure.

No shared caches are used for Boat VMs. This avoids cross-run cache trust and requires fresh dependency and browser downloads; compare observed durations to the deadlines before adding a separately reviewed cache. GitHub-hosted publishing, deployment and production migration remain separate and retain their existing permissions and gates. Validate any provider/timeout changes with isolated runs, failure and cancellation probes, artifact retrieval and sandbox absence before rollout.
