## Pi 1.3.0: source-backed Terra registration

Root observed `pi --list-models gpt-6.1-terra` returns no match. Pi's installed 1.3.0 `docs/models.md` and `dist/core/model-config.js` accept an added model at `$HOME/.pi/agent/models.json`; `dist/core/provider-composer.js:83-117,149-180` requires an API and base URL, supplies zero costs and 128000/16384 token defaults when omitted, and adds/replaces the named model under the provider. The following scratch-only entry specifies actual published capabilities and rates rather than accepting those defaults. It uses the built-in OpenAI provider's separate private `auth.json` key; it contains no credentials:

```json
{
  "$schema": "https://pi.dev/schemas/models.schema.json",
  "providers": {
    "openai": {
      "baseUrl": "https://api.openai.com/v1",
      "api": "openai-responses",
      "models": [{
        "id": "gpt-6.1-terra",
        "name": "GPT-6.1 Terra",
        "reasoning": true,
        "thinkingLevelMap": { "off": "none", "minimal": null, "xhigh": "xhigh", "max": "max" },
        "input": ["text", "image"],
        "contextWindow": 1050000,
        "maxTokens": 128000,
        "cost": { "input": 1, "output": 5, "cacheRead": 0.05, "cacheWrite": 1.25,
          "tiers": [{ "inputTokensAbove": 272000, "input": 2, "output": 7.5, "cacheRead": 0.1, "cacheWrite": 2.5 }] }
      }]
    }
  }
}
```

The [OpenAI model page](https://developers.openai.com/api/docs/models/gpt-6.1-terra) specifies `xhigh`, the text/image modalities, context and output limits, standard rates and over-272k tier, and states **tool calling requires Responses API**. Cost fields are Pi estimates in dollars per million tokens (`pi-ai/dist/models.js:647-666`); these reflect standard 30-minute cache rates and omit service-tier, regional, and retention differences, so they are not a billing guarantee. Verify current rates if reused. The schema permits `thinkingLevelMap` string/null values and the four cost fields plus tiers (`schemas/models.schema.json`); `minimal: null` disables the undocumented minimum level. Crucially, installed `pi-ai/dist/models.js:679-706` hides `xhigh` and silently clamps the request unless an explicit non-null xhigh mapping exists. The Responses implementation (`pi-ai/dist/api/openai-responses.js:281-299`) transmits the mapped value as `reasoning.effort`.

Select `openai/gpt-6.1-terra:xhigh` exactly and separately set `defaultThinkingLevel` to `xhigh`. Stored `auth.json` credentials take precedence over `models.json` and environment (`docs/models.md`); ensure only the scratch OpenAI API-key entry exists. Root should validate in the isolated sandbox that `pi --list-models gpt-6.1-terra` now lists the exact ID, and that the actual Pi session records provider/model and `thinkingLevel: xhigh` and produces a real completed response with functioning FTown mail/tools.
