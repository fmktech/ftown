## Quality and isolation

- Config has 90s test timeout and 15s expect timeout, but no `use.actionTimeout` (`playwright.config.ts:57-65`), so locator action waits can consume a long test's full 180–300s timeout. A focused, separately reviewed improvement is `use.actionTimeout: 15_000` (or 30_000 if observed normal latency needs it); maintain explicit longer assertions/polling and verify actual action latencies across focused trust and shared tests before selecting the number. This bounds the reported pointer-interception failure; it does not fix its cause and must not be used as a retry or coverage reduction. Avoid claiming a passing-run speedup.
- Fixture `helpers/fixtures.ts:4-9` releases test-owned browser approvals, not sessions. `direct-transport.spec.ts:80-90,109-122,133-145,158-175` creates three real sessions and closes contexts without deleting the IDs. They remain in the shared bridge for the run, increasing cumulative state and potentially contaminating later assertions. A repair should track each ID immediately after discovery and delete only that ID in `finally`, while still closing the context even if deletion fails; handle a create-success/discovery-failure path without deleting unrelated sessions. This is an isolation improvement, not proven timing gain. Do not globally clear the shared bridge or enable parallelism without examining all shared fixture ownership.
- The real UI login helper creates a fresh source per browser context and pairs the shared account (`helpers/app.ts:65-96`); test-owned browser cleanup is intentional. Avoid global storage-state/browser approval reuse as a shortcut: it alters the authentication boundary and can introduce shared mutable approvals.
- The job includes much more than Playwright: `scripts/ci/run-job.sh:83-101` installs OS/Chromium dependencies, starts infrastructure, builds and tests UI/bridge, runs DB and security smoke checks, starts services, then Playwright. In the sample, Playwright alone is 318.635s and whole job 513s. A <300s job goal needs measurement of setup/build time and the exact current baseline, not just deleting the 0.78s landing duplicate. Do not drop those checks or change protected environment selectors as an unmeasured shortcut. Preserve cleanup and endpoint/scratch guardrails `run-job.sh:38-80`.
- E2E-02's trust plan will be the material performance lever; changes here cannot by themselves substantiate reaching <300s.
