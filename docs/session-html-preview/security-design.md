# Session HTML preview: security contract proposal

Discovery at base `9693fbb`. This is a design review, not a claim that unimplemented protections are already present. P3 owns only this report; application sources were read-only. No installs, tests, services or browser sessions were started. The architect's v1 decision is one self-contained UTF-8 HTML file (inline CSS/JS and data images), at most 1 MiB, transported in at most 96 KiB raw-byte encrypted chunks. Sibling assets and a public resource server are excluded.

## Threat model and scope

Treat preview bytes as untrusted active browser content, even when a trusted local OS user deliberately registers the file. A generated page or third-party markup may try to read dashboard DOM/storage/credentials, request local-network services, navigate the browser, forge a parent message, or consume browser resources. A remote registered browser/MCP principal may try to turn preview reads into arbitrary host-file reads, cross-session disclosure, stale-content recovery after clear/removal/revocation, or unbounded memory/disk work. The bridge's registered private path, approved source bytes, encryption keys, terminal credentials and other sessions are separate assets.

Trust boundaries are: local CLI registration → bridge private state; host filesystem → bounded snapshot; encrypted principal/session request → manifest/chunk; returned bytes → sandboxed document. The trusted OS registrant already has host filesystem/process authority. V1 prevents ordinary traversal/symlink mistakes and remote path selection; it does **not** claim protection against a malicious same-UID process racing path components or modifying bridge-private state.

## Existing foundations that must remain intact

- `bridge/src/security/bridge/security.ts:121–142,165–197` checks authenticated application/route correspondence and revalidates permission. A command's outer session/bridge context must match its inner payload. New preview commands need explicit read entries in the fail-closed table (`permissions.ts:4–11,60–74`), not a generic file-read capability. Direct terminal transports permit only terminal routes (`security.ts:123–125`); do not bypass that boundary for preview data.
- Local CLI identity is a verified endpoint kind, not a spoof-resistant agent-session identity. `security.ts:170–173` restricts `callerSessionId` to local CLI principals, and `local-api-server.ts:240–244` adapts it to an internal header. Registration/clear must check **verified `principal.endpoint.kind === 'local-cli'`** plus the required control permission before HTTP adaptation; checking Origin, loopback address, caller headers or generic control permission alone is insufficient. Browser/MCP endpoints must not register paths, even if they can otherwise control sessions.
- The serialized encrypted envelope is capped at 450,000 bytes (`bridge/src/security/crypto.ts:7–8,100–117`). Internal HTTP response JSON is capped at 300,000 bytes (`local-api-server.ts:248–255`), and event pages have a 250,000-byte bound (`:229–238`). A 96 KiB raw slice becomes 131,072 base64 characters and roughly 175 KiB after encryption's second base64 expansion, leaving room for small metadata. Assert actual serialized sizes; never send the whole 1 MiB document in a session event or one response.
- `SessionStore.saveSession` serializes writes and uses temporary-file rename (`session-store.ts:51–84`), while the higher-level controller must serialize a full load/mutate/save. Removal marks sessions retired. Do not let preview refresh or cleanup resurrect a removed session.
- `toWireSession` currently strips **only `env`** (`bridge/src/session-wire.ts:3–14`). A new private path on the persisted Session would otherwise flow into existing list/get/update/archive responses. Prefer a separate private registration store, or centrally remove the private field from every egress and use a distinct wire type. Browser metadata must contain only registered/status/generation/revision/byte count and a safe display label if needed.
- Browser command responses are correlated to expected request/bridge identities (`ui/src/lib/secure-message-client.ts:196–210`), requests have a 40-second deadline (`:214–223`), and disposal rejects pending work (`:227–234`). A preview hook also needs its own selected-session generation/cancellation checks so old successful responses cannot render in a new session.

## Architecture decision

| Option | Assessment |
|---|---|
| Bounded encrypted bytes → opaque sandbox `srcdoc` | Recommended. Preserves existing E2EE routing and needs no network URL, token in markup, asset broker or new cross-origin protocol. |
| Parent-created Blob document | Possible, but unnecessary for one inline document; introduces URL lifetime/cleanup and URL-sharing concerns. It does not solve arbitrary-script self-navigation. |
| Authenticated HTML/asset resource endpoint | Reject for v1. Ordinary iframe requests cannot use the current encrypted application channel; bearer URLs leak capabilities, browser cookies introduce another authorization boundary, and an origin/resource server creates more exposure. |
| Relative sibling asset rewriting or postMessage filesystem broker | Reject for v1. It adds parsing, CSS/module/reference resolution, path authorization and browser-to-host capabilities. No preview-to-terminal or preview-to-host message channel is needed. |

Do not parse or mount preview HTML in the dashboard DOM. No `dangerouslySetInnerHTML`, script execution, DOMParser-based asset rewriting, parent-created JavaScript bootstrap containing file bytes, or “open raw in app-origin tab” feature. The document string may be assigned only to the sandboxed iframe's `srcDoc`, preceded by the fixed policy prelude. Parent labels/status/errors render as ordinary React text.

## Required invariants before implementation freeze

1. **Registration is an exact-file export capability.** Local CLI registers one file for an existing session, with no browser-provided read path. If session-root confinement is selected (P1 recommendation), require a real explicit session working directory; relative paths resolve there, absolute paths must remain inside it using path-component containment, never a string-prefix test. No fallback to bridge cwd/home. Root must freeze whether outside-workdir registration is unsupported rather than let workers choose inconsistently.
2. **Private path and safe reads.** Validate NUL/empty/malformed paths; resolve and store a canonical private target. Prevent ordinary symlink escape at registration and every refresh, including symlinked parent components. Open the final component with no-follow where supported; require a regular file, bound bytes while reading, and check descriptor metadata before/after. Reject directories, devices, FIFOs and sockets before reading. A missing file is a bounded `missing` state; do not overwrite the registration or expose raw filesystem errors. `realpath` then `open`, or final-component `O_NOFOLLOW` alone, is not adversarial race-proof; document the trusted-local-OS assumption.
3. **No secret/path egress.** Never place absolute path, source path, working-root-derived label, raw stat error, credential, token, grant or terminal environment in public preview metadata, events, errors or logs. The HTML naturally contains whatever its trusted registrant chose to export; the system must not inject host credentials or hidden files into it. Registration requests/private storage may hold the path inside existing local encryption/private persistence.
4. **Identity and authorization at every read.** Require a verified authorized read principal for the target bridge/session on manifest and every chunk. Enforce registration-local-only separately from read/control permissions. Revalidate after awaited filesystem work and before releasing sensitive bytes if revocation could occur during that work. Deny wrong owner, wrong bridge, unknown/deleted session, unapproved/revoked endpoint, pending MCP grant and requests that bypass normal encrypted dispatch. No cleartext fallback.
5. **Bounded snapshot protocol.** A manifest identifies registration generation + content revision (SHA-256 of exact raw bytes), byte length, chunk size/count and encoding. Each chunk is bound to that generation/revision/index or bounded aligned offset, includes enough metadata to validate correlation, and contains at most 98,304 raw bytes. Inputs are safe integers, with explicit bounds. Chunk reads either return bytes matching the requested immutable revision or a typed stale result; never mix revisions.
6. **Clear/removal/replacement invalidates content access.** Old generation/revision requests fail after clear, re-register, session removal or revoked access, even if a cache still holds bytes. Re-registering identical bytes must still change the registration generation. Otherwise digest-only IDs could let an old request silently attach to a new export. Revival with a new session ID starts unregistered. Clearing metadata never deletes the user's artifact.
7. **Assembly validates before rendering.** Allocate only after validating manifest ≤1,048,576 bytes and at most 11 chunks at 96 KiB. Reject malformed/noncanonical base64, unexpected chunk offsets/lengths, duplicates, missing/truncated chunks, conflicting metadata and total length/hash mismatch. Assemble bytes first, then decode once using fatal UTF-8 decoding so a multibyte sequence spanning chunks is preserved. Do not silently replace invalid UTF-8. Render only a complete verified document.
8. **Refresh is bounded and cancelable.** About one-second polling only for the selected visible open preview; one status request and one bounded assembly at a time. Stop on close/switch/unmount/disconnect/removal, discard late responses, and reconcile on reconnect. Status/content changes must not trigger broadcast content fanout or unbounded cache/watchers. Bound bridge concurrent snapshot work globally/per session and coalesce identical in-flight reads; a 1 MiB file multiplied by unlimited viewers is not a bounded design.
9. **Completed-write semantics are honest.** Pre/post stats and identical successive polls detect many incomplete edits, but a writer can pause mid-write. They cannot prove producer completion. Recommend producer writes to a sibling temporary file and atomically renames to the registered path; polling supports this. Freeze the v1 guarantee as coherent/stable bytes plus documented atomic-producer guidance, or introduce an explicit completion signal. Do not promise arbitrary in-place writes are always complete.
10. **Sandbox is immutable and opaque.** Use `sandbox="allow-scripts"` only, set from the first render. Never add `allow-same-origin`, forms, popups, downloads, modals, top navigation, storage access or popup escape flags. Use a descriptive title and `referrerPolicy="no-referrer"`; do not assign a name/capability or credential-bearing URL. Removing/changing the registration or document generation replaces the iframe and clears prior execution state. Parent-owned close/tab controls stay outside the frame.
11. **Policy precedes every untrusted byte.** Prefix a fixed valid doctype/head with the CSP meta and referrer meta before the supplied HTML. Do not insert it after an untrusted `<head>`, script, image, meta refresh or parser construct. Apply the same fixed prelude to every revision. CSP meta cannot supply `sandbox`/`frame-ancestors`; sandbox must be the iframe attribute. Source-provided later CSP can only further restrict, not replace the first enforced policy.
12. **Minimal supported resource policy.** Suggested fixed policy: `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; connect-src 'none'; font-src 'none'; media-src 'none'; object-src 'none'; frame-src 'none'; child-src 'none'; worker-src 'none'; manifest-src 'none'; base-uri 'none'; form-action 'none'`. No `'self'`, app origin, `https:`, `http:`, blob script, external script, `unsafe-eval` or reporting endpoint. This supports inline scripts/event handlers, inline styles and data images. Relative assets, fetch/XHR/WebSocket/EventSource/beacon, external CSS/imports/fonts/media, workers, nested frames, eval/new Function and WASM compilation are outside v1. Avoid console/UI claims that every JavaScript library is supported.
13. **No host feedback capability.** Do not add a window message listener for preview events, RPC, navigation, filesystem access, terminal input or resizing. A frame can call `parent.postMessage` despite being opaque; origin `null` is not an identity. Existing source search found service-worker/MessagePort/socket handlers, not a dashboard `window` message capability. Test forged messages against the final app. Future messaging needs a separately reviewed explicit protocol.

## Browser isolation limits: explicit compatibility/security conditions

An opaque sandbox protects dashboard DOM/storage access; it is **not a full network or resource-execution sandbox**. Arbitrary script can navigate its own iframe to another HTTP URL. Meta refresh and links can also navigate it. The initial document's fetch/subresource policy does not provide a portable blanket navigation-denial mechanism. Such a navigation may make a request (potentially with browser-managed cookies appropriate to the target), even though sandbox restrictions persist and the preview cannot read app DOM/storage. Do not claim zero egress, complete CSRF protection for arbitrary other sites, or guaranteed absence of local-network requests. Do not rely on experimental iframe `csp`/`credentialless` or an unsupported `navigate-to` directive to prove that property.

Removing obvious link/meta navigation markup or handling clicks is optional usability hardening, not a security proof: arbitrary allowed script can still assign its own location. A reliable zero-egress requirement would need a different execution architecture or browser-enforced request controls beyond a portable iframe. The architect explicitly accepts/documented this limitation for v1 while keeping all host capabilities absent.

Similarly, source-byte and transfer limits do not bound arbitrary JavaScript CPU/heap use; an infinite loop can degrade the tab, and srcdoc isolation does not promise a separate renderer process. No timeout in the parent proves termination. Keep the source trusted-local-export model and ordinary browser recovery expectation explicit.

Standards basis: the [HTML iframe specification](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox) describes opaque-origin forcing and the capabilities re-enabled by sandbox tokens; the [CSP specification](https://w3c.github.io/webappsec-csp/#meta-element) requires policy metadata early because earlier content is not covered, and limits directives supported in meta. The [srcdoc documentation](https://developer.mozilla.org/en-US/docs/Web/API/HTMLIFrameElement/srcdoc) explains its parent-DOM risk without an opaque sandbox; the [iframe documentation](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) distinguishes script permissions from top-navigation permissions. Parent page headers in `ui/next.config.ts:9–15` protect framing of the dashboard, not preview-document resource access.

## Acceptance and negative tests

Bridge/unit or in-memory checks, run by the assigned implementation worker only within its non-server lease:

- Local CLI register/read/clear succeeds; browser and MCP principals with control cannot register or clear a path. Invalid IDs, wrong bridge/session/owner and unknown session fail before disk access. Register via an alias/generic session PATCH or `mcp_request` must not bypass the restriction.
- In-root regular file succeeds; missing/rootless session, `../` escape, prefix-collision sibling root, absolute escape, NUL, final/parent symlink and directory/FIFO/device fail without hangs or path-bearing errors. Follow the approved non-adversarial-race scope.
- Registration/clear survives restart, removal invalidates stale reads, revival is unregistered; simultaneous metadata edits do not overwrite each other. Search list/get/session-update/archive/error/log payloads for a private-path sentinel.
- Exact 1 MiB UTF-8 document and exact chunk edges succeed; +1 byte, invalid UTF-8, split emoji, malformed/out-of-range indexes, changed/re-registered same bytes, modified file mid-assembly and revoked principal during awaited read fail correctly. Hash plus total length detect mixed/truncated bytes.
- Multiple active readers cannot cause unbounded allocations/work; source growth after initial stat is bounded by the actual read cap. No unbounded `readFile` before stat/limit enforcement. Chunks satisfy actual HTTP/encrypted serialization limits.

Root-only browser/runtime/E2E gates:

- Benign counter/button script changes only its own preview; inline CSS and data image work. Parent DOM, cookies/localStorage, service worker and terminal/secure client are inaccessible. Forged `postMessage` produces no host operation. No app credential or private path is present in rendered source.
- Capture requests from frame fetch/XHR/beacon/WebSocket, image, script, CSS/import/font/media, iframe/object, worker and form attempts; ordinary requests are blocked under the prefix CSP/sandbox. Use task-local sinks, not public hosts. Separately demonstrate/document self-navigation as the accepted limitation; do not write a false test asserting it cannot issue a request.
- Popup, download, top navigation and modal attempts do not acquire those capabilities. Source-provided `<base>`, CSP meta and early script cannot weaken the fixed policy. Test malformed full-document markup to ensure policy is still the first enforced content.
- Replace the source atomically: only a complete new revision renders and its local state resets. Switch session/close/reopen while chunks are in flight: old content never appears in another session; closed preview does not keep polling. Disconnect/revoke clears/stops sensitive rendering as defined by the UI contract. Test cloud and local encrypted routes, desktop split and mobile tabs.

Package commands already present: `cd bridge && npm run build`; targeted non-server `node --import tsx --test src/<owned-test>.test.ts`; `cd ui && npm test -- --run <owned-test>` and `npm exec tsc -- --noEmit`. Full bridge `npm test` includes servers and belongs to root, as do rendered/browser tests and all E2E.

## Design absence checklist

| # | Item | Design verdict / implementation gate |
|---|---|---|
| 1 | Authentication | checked-clean foundation; new reads/mutations must stay behind verified encrypted dispatch, no public endpoint. |
| 2 | Function authorization | Required local-CLI-only registration/clear and read-only retrieval; generic control is insufficient. |
| 3 | Object authorization | Required bridge/session/generation binding and per-chunk revalidation. |
| 4 | Input validation | Required bounded file, chunk, UTF-8, manifest and path validation. |
| 5 | Injection/path traversal | Required exact-file capability and ordinary symlink protection; no shell/SQL sink needed. |
| 6 | XSS | Active HTML intentionally executes only in immutable opaque sandbox, never parent DOM. |
| 7 | Secrets | Required private-path projection and no host capability/credential injection. |
| 8 | Deserialization | n.a. to object-instantiation formats; JSON/base64/UTF-8 must still be bounded. |
| 9 | SSRF | No bridge/server URL fetch; browser self-navigation remains the explicit limitation above. |
| 10 | Uploads | No anonymous upload route; trusted-local registration still requires byte/type bounds. |
| 11 | Abuse | Required bounded work/concurrency/poll lifecycle; arbitrary JS runtime resources remain unbounded. |
| 12 | Error/info leak | Required typed generic states/errors with no source path/raw OS errors. |
| 13 | CORS | No new cross-origin resource endpoint or wildcard CORS; opaque frame is not an authenticated caller. |
| 14 | Headers/CSRF | Required sandbox attribute, early CSP and no-referrer; do not claim navigation/CSRF guarantees the browser does not provide. |
| 15 | Dependencies | n.a. to current design: no added renderer/asset-rewriter dependency is needed. Review any later proposal separately. |

## Peer proposal review and handoff

P1 `bridge-discovery.md` is approved subject to the invariants above: principal-kind guard before HTTP adaptation; no private path through `toWireSession`/archive egress; registration-generation invalidation even for identical-byte replacements; serialization limits checked; no claim of hostile local race safety or producer-write completion from polling. Its per-chunk bounded reread-and-digest option is correct under these constraints; a future snapshot cache needs independent TTL, memory and invalidation bounds. Root must freeze the root-confinement policy and stale-result states in the compiler-enforced contract.

P2 `ui-discovery.md` is reviewed and approved. Its one shared RPC, explicit target identities, generation fences after every await, complete-revision verification, bounded polling and iframe policy satisfy this proposal. It correctly distinguishes stopping future chunks/discarding a late result from canceling an already published RPC, and correctly treats Terminal Local/P2P connectivity as separate from hosted command availability. No browser endpoint, resource broker, origin privilege or frame feedback channel is proposed. Manual Refresh resetting unchanged iframe state is the architect's small UX choice, not a security freeze blocker. No existing application vulnerability is asserted solely from these design requirements.

### Root draft contract review

Reviewed `contract.md` after its capability/archive/font/CSP/compact-layout update. Its 1 MiB/96 KiB limits, bounded read concurrency, strict chunk reassembly, session-generation cancellation, private-field egress projection, read-only commands and opaque iframe policy satisfy this security proposal. No additional architecture is needed. Freeze with these narrow clarifications:

- Construct a fixed literal prefix `<!doctype html><html><head><meta charset="utf-8"><meta http-equiv="Content-Security-Policy" content="[the fixed policy, with quoted 'none' and 'unsafe-inline' keywords]"><meta name="referrer" content="no-referrer"></head><body>`, concatenate the untrusted document, then append `</body></html>`. The policy is therefore parsed before any original doctype/head/script. Do not parse/extract the untrusted head in the parent or use it to construct the prefix. Test full-document and malformed markup, not just a body fragment.
- Make wrapped-route behavior explicit: reject preview PUT/DELETE through `mcp_request` outright, or pass the same verified local-CLI kind guard before any handler. Direct and wrapped dispatch must not differ in authorization; an internal caller header is never sufficient proof.
- State the coherent-byte snapshot guarantee and atomic-producer guidance explicitly. Do not claim polling proves an in-place writer completed.
- P1 identified a session update/removal ordering issue. Its bounded shared-mutation-queue fix must ensure a pending registration cannot publish success or resurrect metadata after removal; no wider session redesign is requested.

P2 review is complete. Application writes remain unauthorized to P3.

Reviewed root-authored `bridge/src/preview-protocol.ts`: constants and type-only shapes are approved. Types deliberately do not enforce UUID/hash/base64/integer syntax; boundary implementations must enforce the frozen runtime constraints. No source path belongs in a wire result.

P1's bounded ordering resolution is approved: factor the existing controller queue into `withSessionMutation<T>`; update/register/clear/remove use the same per-session production pump queue, with the existing metadata queue as the fallback. `removeFtownSession` keeps its separate store lock and must not reacquire the pump queue; externally prelocking remove callers/tests must switch to direct controller removal. After filesystem I/O, a preview read rechecks registration ID and private source within that same queue. This defines a read linearization point before or after a competing mutation; it does not retract bytes already authorized/in flight before a later clear/removal. Test paused reads versus clear/register/remove and ensure removal wins without a stale success publication or metadata resurrection. No wider lifecycle refactor is required.

The evidence-backed extension to existing stale writers is approved within the same queue: usage collection occurs outside, then reload/check/save/publish inside; retry loads and relaunches inside; startup resurrection injects that same queue. **Resurrection must reload the current session inside its acquired queue before decisions/mutation**, rather than merely queueing a stale object obtained from the initial session listing. Otherwise a registration committed before queue acquisition can still be erased. Keep terminal-pump/hooks already using the queue unchanged, preserve distinct-session concurrency, avoid nested acquisition in helper calls and preserve lifecycle rollback. Test forced schedules against register/clear/remove for usage, retry and resurrection; no sidecar architecture is necessary.

Final prefreeze P3 decision: approved with the explicit wrapper, wrapped-route authorization and queue/reload requirements above.
